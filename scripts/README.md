# Работа с базой

Изменения схемы выполняются отдельными последовательными миграциями из
`migrations/`. Каждый файл сначала проверяется на изолированной локальной БД.
Рабочая база и публикация изменяются только с явного разрешения владельца.

## Отозванные скрипты

Следующие файлы удалены из использования, исходники остаются в истории Git:

- `schema.sql` — удалял таблицы и создавал открытые политики записи;
- `full-seed.sql` — пересоздавал таблицы и заново заполнял каталог;
- `seed-supabase.mjs` — подключался к БД и очищал таблицы перед импортом;
- `generate-full-sql.mjs` — повторно создавал опасный `full-seed.sql`.

Старые команды больше не выполняются. Автоматического сброса или импорта
в рабочую базу в проекте нет. `parsed-data.json` и CSV сохранены как исходные
данные, но не являются актуальной копией рабочей БД.

`parse-csv.mjs` — старый локальный конвертер, не подключается к БД. Он зависит
от уже отсутствующих `src/data/prices.json` и `src/data/promotions.json`;
пока не восстановлены метаданные, использовать его нельзя.

`add-updated-at.sql` оставлен для старых установок, но не заменяет миграции.
Его функция теперь также задаёт безопасный `search_path`.
